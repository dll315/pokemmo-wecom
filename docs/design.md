# PokeMMO 中文报点推送：设计

用户要求：持续关注 Alphapedia，面向中文用户，推送头目与群怪到企业微信群机器人；部署于 Linux 服务器或 NAS。

## 已核实的接口

读取公开 `/history`、`/swarm-history` 页面取得各自的临时 token 和会话 cookie，按网站自身前端的方式调用 `/api/history-data`、`/api/swarm-history-data`。明确设置 `tz=UTC`，没有时区后缀的 `timestampIso` 按 UTC 解析。按覆盖监控窗口的 UTC 日期筛选，读取该日全部分页，再按报点时间筛选；不依赖分页排序，不以递增 ID 判断新旧。

头目链接的 timestamp 是预计消失时间。群怪历史链接的 timestamp 不能单独用来判断仍在场：实测水箭龟历史链接给出了较晚的时间，但 `/api/swarm-call-status` 返回 expired 与更早的 effective_despawn_timestamp。所有群怪发送前必须核实这一状态。网站未提供稳定性保证，结构变化或权限失败显示错误，绝不将空响应视为正常。

ntfy 当前可读取但补收请求返回空内容；初版直接监控公开历史接口，每 30 秒核对两种报点。可调范围为 15–3600 秒，失败退避，不绕过登录、验证码或访问限制。

## 程序与部署

Node.js 22+，零第三方运行依赖。Docker / Compose 是 Linux、NAS 的主要方式，也支持直接运行。中文首页无需登录，提供实时报点、最近24小时历史、地区群怪、四个时间窗和中文头目资料；后台在 /admin，初始密码按用户要求为123456。管理界面提供配置、消息预览、状态、日志、测试消息、失败重试和暂停。默认部署端口仅绑定本机，可显式改为局域网地址。Webhook 仅保存在服务端，访客接口按字段白名单输出，不包含管理配置、发送队列、日志或密钥。

仅有一个长期运行进程；数据目录持久化并取得独占锁。JSON 状态原子替换，保留备份；损坏且不能恢复时停止，禁止默默重置。持久化事件身份、队列、发送结果、扫描进度；首次只发送仍有效的报点，过期信息不补发。暂停期间继续观察但不生成发送任务。开启某类推送时仅推送新出现/仍有效的事件，不重放旧记录。

中文宝可梦名、地区与地点来自网站公开简体中文数据，并附来源与缓存日期。找不到可靠中文译名时保留原文，不猜译。通知展示报点时间、预计消失时间、来源、剩余时间、对应详情链接。所有时间为北京时间。

## 正确性与不确定性

事件键包含类型与源记录 ID；内容指纹区分更正。发送成功必须同时满足 HTTP 成功、JSON 可解析、企业微信 errcode 为数值 0。明确失败保留任务，限流和临时业务错误延迟重试；请求超时、连接中断、无效响应或发送过程中崩溃，无法知道对端是否收到，记为“结果待确认”，禁止自动重发，由用户在界面确认后重试或忽略。企业微信不提供业务幂等键，因此不宣称绝对不重复。

每次发送前检查开关、是否过期；群怪再查状态。不发送 unknown、removed、ended_early 或 expired 群怪的新报点。已发送的群怪若在报点后三小时内被撤回或提前结束，发送一条中文状态更正；入队与发送采用相同年龄门槛，过旧更正不阻塞新报点。相同更正只通知一次。最近24小时历史中的已核实状态不会被后续未核实扫描覆盖。源接口异常显示错误，不发送缺少关键字段或链接不匹配的报点。

## 验证

先建立失败测试，再实现：真实样本的 UTC 和 timestamp 语义、群怪状态覆盖、中文回退、首次启动、分页与非单调 ID、重启去重、原子存储恢复、企业微信 HTTP200业务失败、限流、超时不盲目重试、过期任务、管理接口鉴权与密钥脱敏。用本地 HTTP 服务验证实际请求体与端到端入队/发送，再运行真实网站只读检查。没有用户机器人地址时不宣称真实群送达。
