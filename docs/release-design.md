# 1.2 发布设计

用户已授权：详细中文头目通知、简洁群怪通知、后台管理推送链接、公开 GitHub 仓库 dll315/pokemmo-wecom，以及任何人可匿名拉取并用一条 docker run 部署。

头目通知按物种＋地区＋地点精确匹配目录，包含中文名称、具体位置、招式、特性、通行技能、地点条件、捕捉备注和预计消失时间。缺少对应资料时明确写暂无，不混用其他地点的招式。群怪正常通知仅名称和位置；撤回或提前结束附必要状态更正。超过企业微信4096字节时优先保留核心信息，截短备注。

推送链接可增删改、启停、选择头目／群怪与逐个测试。管理 API 要求登录，不回显原始密钥。多个目标独立去重、队列、发送结果、重试和限流；结果不确定不自动重发。原单链接配置迁移为默认目标，已有成功记录保持去重。

Docker 使用 /data 命名卷、默认端口8787和后台初始密码123456。容器用系统 flock 锁保证跨容器互斥，退出自动释放；普通 Node 运行保留现有本机实例锁。无需固定 hostname 或复杂命令。

发布代码前执行本地测试、浏览器验证、密钥扫描和独立审查。GitHub Actions 执行 Linux 测试、实际镜像构建和容器启动／重建持久化检查，发布 amd64 与 arm64 镜像到 GHCR。公开仓库不等于公开镜像；最终必须独立核实镜像匿名读取，不能把私有镜像当作任何人可部署。

实施顺序：通知格式→多链接与迁移→后台界面→Docker锁与启动检查→发布工作流与文档→本地检查→公开提交→云构建与匿名拉取验证。仅上传源代码、公开数据和说明；runtime、artifacts、密码文件和机器人密钥禁止上传。
